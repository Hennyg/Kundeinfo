# FilBackupStatusSwa - Azure Static Web Apps-version

Samme funktion som `FilBackupStatusServer`, men bygget til Azure Static Web
Apps: Azure Functions (isolated worker, .NET 8) i stedet for en almindelig
ASP.NET Core-app, Table Storage i stedet for lokale JSON-filer, og Azure
Communication Services Email i stedet for SMTP.

## Mappestruktur

| Mappe/fil | Formål |
|---|---|
| `app/` | Minimal statisk placeholder-side (SWA kræver en app-mappe) |
| `api/` | Selve Azure Functions-koden |
| `staticwebapp.config.json` | Routing-konfiguration for SWA |

## Dashboard

`app/index.html` er et statusdashboard, ikke længere kun en placeholder. Det
kalder `/api/status` (samme origin som selve SWA'en, så ingen CORS-opsætning
nødvendig) og viser seneste rapport pr. kunde som farvede kort - rødt ved
"fejl" i emnet, gult ved "ingen ny backup", grønt ellers.

**Om API-nøglen på dashboardet:** siden beder om jeres `ApiKey` første gang I
åbner den, og gemmer den kun i browserens `sessionStorage` (ryddes når fanen
lukkes) - den ligger aldrig i selve koden eller filen. Alle med nøglen kan se
dashboardet, præcis som alle med nøglen allerede kunne kalde `/api/status`
direkte - dashboardet ændrer ikke ved hvem der kan se hvad, det gør det bare
læsbart i en browser i stedet for rå JSON.

## Endpoints

Samme som App Service-versionen:

| Endpoint | Formål |
|---|---|
| `POST /api/report` | Kaldes af kunde-PC'erne. Header `X-Api-Key`, JSON-body `{customerName, movexNumber, subject, body}`. |
| `GET /api/status` | Seneste rapport pr. kunde (samme `X-Api-Key`) - bruges nu af dashboardet i `app/`. |

Der er ingen `/health`-endpoint i denne version - Azure Functions har sin
egen indbyggede overvågning via Application Insights (se nedenfor).

## Forudsætninger i Azure (opsæt i denne rækkefølge)

1. **Storage Account** - almindelig Azure Storage Account, bruges til Table
   Storage. Kan være samme, som SWA evt. opretter automatisk, eller jeres eget.
2. **Azure Communication Services**-ressource, med en **Email**-tjeneste
   tilknyttet. Under opsætningen skal I enten:
   - bruge Azures eget testdomæne (`*.azurecomm.net`) - virker med det samme,
     godt til test, men mails kan lande i spam hos modtageren, eller
   - verificere jeres eget domæne (kræver DNS-records) - anbefales til
     produktion.
3. **Static Web App**-ressourcen selv, med `api/`-mappen tilknyttet som
   "Managed Functions".

## Managed Identity - vigtigt forbehold

Planen var at bruge Managed Identity, så der slet ingen hemmelighed skal
gemmes for at få adgang til Table Storage og ACS Email. Det kræver at jeres
SWA-niveau/Function-integration understøtter en system-tildelt identitet på
den måde, en almindelig separat Azure Function App gør. **Jeg kan ikke
bekræfte fra her, om det er tilfældet for netop jeres SWA-niveau** - det kan
have ændret sig, og jeg har ikke adgang til at slå det op live.

Sådan finder I ud af det, og hvad I gør i hvert tilfælde:

- **Hvis Managed Identity kan slås til** på jeres SWA-ressource (under
  **Identity** i Azure-portalen): giv den identitet rollen **Storage Table
  Data Contributor** på jeres Storage Account, og rollen **Communication and
  Email Service Owner** (eller en mere afgrænset custom-rolle, hvis I vil
  være strammere) på ACS-ressourcen. Sæt kun `AcsEndpoint`
  (ACS-ressourcens URL) som app-setting - **lad `AcsConnectionString` stå
  tom**. Koden bruger så `DefaultAzureCredential` automatisk.
- **Hvis Managed Identity ikke er en mulighed**: sæt `AcsConnectionString`
  som app-setting i stedet (findes under ACS-ressourcen -> Keys). Det er
  stadig krypteret af Azure i Application Settings, bare ikke helt
  hemmeligheds-frit. Funktionelt uændret i forhold til App Service-versionen.

I begge tilfælde skal `AzureWebJobsStorage` (forbindelsen til jeres Storage
Account til selve Table Storage) sættes som app-setting - Functions kræver
den under alle omstændigheder for sin egen drift, uafhængigt af Managed
Identity-spørgsmålet ovenfor.

## Lokal udvikling

1. Installer [Azure Functions Core Tools](https://learn.microsoft.com/azure/azure-functions/functions-run-local) og .NET 8 SDK.
2. Udfyld `api/local.settings.json` (denne fil deployes ALDRIG, kun til lokal brug):
   - `AzureWebJobsStorage`: enten `UseDevelopmentStorage=true` (kræver
     [Azurite](https://learn.microsoft.com/azure/storage/common/storage-use-azurite)
     kørende lokalt) eller en rigtig (gerne test-)Storage Account connection string.
   - `ApiKey`: en genereret nøgle, samme som klienten skal bruge.
   - `AcsConnectionString`: nemmest til lokal test - virker uden Managed
     Identity-opsætning. Alternativt, hvis I er logget ind med `az login` og
     vil teste selve Managed Identity-flowet, sæt kun `AcsEndpoint` -
     `DefaultAzureCredential` finder automatisk jeres CLI-login lokalt.
3. Kør fra `api/`-mappen:
   ```
   func start
   ```
   API'et kører herefter typisk på `http://localhost:7071/api/report` osv.

## Deployment

Nemmest via GitHub Actions, som SWA opsætter automatisk, når I opretter
ressourcen og peger den på jeres repository - angiv `app_location: "app"` og
`api_location: "api"` i den workflow-fil, Azure genererer. Alternativt kan I
bruge SWA CLI (`swa deploy`) til manuel deployment uden GitHub.

## Overvågning

Da der ikke er noget `/health`-endpoint her (Azure Functions overvåges
anderledes end en almindelig webapp), brug i stedet **Application Insights**
(kan tilknyttes SWA/Functions-ressourcen) til at holde øje med fejl og om
`EmailRetry`-funktionen rent faktisk kører som planlagt hvert 10. minut. Sæt
en alarmregel op på fejlrater eller manglende kørsler, så I stadig får besked
udefra, hvis noget går galt med selve tjenesten.

## Hvordan det virker

1. Kunde-PC'en poster `{customerName, movexNumber, subject, body}` til
   `/api/report` med sin `X-Api-Key`.
2. `ReportFunction` gemmer rapporten i Table Storage (`Reports`-tabellen,
   partition pr. kunde, samt `LatestStatus`-tabellen med kun seneste pr.
   kunde) - *før* den forsøger at sende mail. Rapporten går altså ikke tabt,
   selvom selve mailafsendelsen fejler.
3. Mailen forsøges sendt med det samme via Azure Communication Services.
   Lykkes det ikke, lægges den i `PendingEmails`-tabellen.
4. `EmailRetryFunction` kører hvert 10. minut og forsøger at sende alt, der
   stadig ligger i køen.

using FilBackupStatusApi.Services;
using Microsoft.Azure.Functions.Worker;
using Microsoft.Extensions.Logging;

namespace FilBackupStatusApi.Functions;

public class EmailRetryFunction
{
    private readonly PendingEmailStore _pendingQueue;
    private readonly EmailSender _emailSender;
    private readonly ILogger<EmailRetryFunction> _logger;

    public EmailRetryFunction(PendingEmailStore pendingQueue, EmailSender emailSender, ILogger<EmailRetryFunction> logger)
    {
        _pendingQueue = pendingQueue;
        _emailSender = emailSender;
        _logger = logger;
    }

    // Kører hvert 10. minut - cron-udtryk med sekunder: {sekund} {minut} {time} {dag} {måned} {ugedag}
    [Function("EmailRetry")]
    public async Task Run([TimerTrigger("0 */10 * * * *")] TimerInfo timer)
    {
        var items = await _pendingQueue.GetAllAsync();
        if (items.Count == 0) return;

        _logger.LogInformation("Forsøger at sende {Count} ventende mail(s).", items.Count);

        foreach (var item in items)
        {
            try
            {
                await _emailSender.SendAsync(item.Subject, item.Body);
                await _pendingQueue.DeleteAsync(item);
                _logger.LogInformation("Ventende mail sendt: {Subject}", item.Subject);
            }
            catch (Exception ex)
            {
                _logger.LogWarning(ex, "Ventende mail fejler stadig: {Subject}", item.Subject);
                // Bliver liggende i tabellen og forsøges igen næste gang funktionen kører
            }
        }
    }
}

using System.Net;
using System.Text.Json;
using FilBackupStatusApi.Models;
using FilBackupStatusApi.Services;
using Microsoft.Azure.Functions.Worker;
using Microsoft.Azure.Functions.Worker.Http;
using Microsoft.Extensions.Configuration;
using Microsoft.Extensions.Logging;

namespace FilBackupStatusApi.Functions;

public class ReportFunction
{
    private readonly TableReportStore _store;
    private readonly PendingEmailStore _pendingQueue;
    private readonly EmailSender _emailSender;
    private readonly ILogger<ReportFunction> _logger;
    private readonly string _apiKey;

    public ReportFunction(
        TableReportStore store,
        PendingEmailStore pendingQueue,
        EmailSender emailSender,
        IConfiguration config,
        ILogger<ReportFunction> logger)
    {
        _store = store;
        _pendingQueue = pendingQueue;
        _emailSender = emailSender;
        _logger = logger;
        _apiKey = config["ApiKey"] ?? throw new InvalidOperationException("ApiKey mangler i konfigurationen.");
    }

    [Function("Report")]
    public async Task<HttpResponseData> Run(
        [HttpTrigger(AuthorizationLevel.Anonymous, "post", Route = "report")] HttpRequestData req)
    {
        if (!req.Headers.TryGetValues("X-Api-Key", out var keys) || keys.FirstOrDefault() != _apiKey)
        {
            return req.CreateResponse(HttpStatusCode.Unauthorized);
        }

        var body = await new StreamReader(req.Body).ReadToEndAsync();
        ReportRequest? request;
        try
        {
            request = JsonSerializer.Deserialize<ReportRequest>(
                body, new JsonSerializerOptions { PropertyNameCaseInsensitive = true });
        }
        catch
        {
            var bad = req.CreateResponse(HttpStatusCode.BadRequest);
            await bad.WriteStringAsync("Ugyldig JSON.");
            return bad;
        }

        if (request is null || string.IsNullOrWhiteSpace(request.CustomerName) || string.IsNullOrWhiteSpace(request.Subject))
        {
            var bad = req.CreateResponse(HttpStatusCode.BadRequest);
            await bad.WriteStringAsync("CustomerName og Subject er påkrævet.");
            return bad;
        }

        var entity = new ReportEntity
        {
            PartitionKey = request.CustomerName,
            RowKey = Guid.NewGuid().ToString(),
            MovexNumber = request.MovexNumber,
            Subject = request.Subject,
            Body = request.Body,
            EventTimestampUtc = request.TimestampUtc ?? DateTime.UtcNow,
            ReceivedUtc = DateTime.UtcNow
        };

        // Gem rapporten FØRST, uanset om mailen bagefter lykkes - intet må gå tabt
        await _store.AppendAsync(entity);

        var fullSubject = $"[Filbackup] {request.CustomerName} (Movex {request.MovexNumber}) - {request.Subject}";

        try
        {
            await _emailSender.SendAsync(fullSubject, request.Body);
            _logger.LogInformation("Mail sendt for {Customer}: {Subject}", request.CustomerName, request.Subject);
        }
        catch (Exception ex)
        {
            _logger.LogWarning(ex, "Kunne ikke sende mail med det samme - lægges i kø.");
            await _pendingQueue.EnqueueAsync(fullSubject, request.Body);
        }

        var response = req.CreateResponse(HttpStatusCode.OK);
        await response.WriteAsJsonAsync(new { received = true });
        return response;
    }
}

using System.Net;
using System.Text.Json;
using FilBackupStatusApi.Models;
using FilBackupStatusApi.Services;
using Microsoft.Azure.Functions.Worker;
using Microsoft.Azure.Functions.Worker.Http;
using Microsoft.Extensions.Configuration;

namespace FilBackupStatusApi.Functions;

public class StatusFunction
{
    private readonly TableReportStore _store;
    private readonly string _apiKey;

    public StatusFunction(TableReportStore store, IConfiguration config)
    {
        _store = store;
        _apiKey = config["ApiKey"] ?? throw new InvalidOperationException("ApiKey mangler i konfigurationen.");
    }

    [Function("Status")]
    public async Task<HttpResponseData> Run(
        [HttpTrigger(AuthorizationLevel.Anonymous, "get", Route = "status")] HttpRequestData req)
    {
        if (!req.Headers.TryGetValues("X-Api-Key", out var keys) || keys.FirstOrDefault() != _apiKey)
        {
            return req.CreateResponse(HttpStatusCode.Unauthorized);
        }

        var latest = await _store.GetLatestAsync();

        // Mappes til en ren DTO, så frontenden får et stabilt, forudsigeligt
        // format uafhængigt af de interne Table Storage-felter (PartitionKey,
        // ETag, Timestamp osv.).
        var items = latest
            .Select(e => new StatusResponseItem
            {
                CustomerName = e.RowKey,
                MovexNumber = e.MovexNumber,
                Subject = e.Subject,
                Body = e.Body,
                EventTimestampUtc = e.EventTimestampUtc,
                ReceivedUtc = e.ReceivedUtc
            })
            .OrderBy(i => i.CustomerName)
            .ToList();

        var json = JsonSerializer.Serialize(items, new JsonSerializerOptions
        {
            PropertyNamingPolicy = JsonNamingPolicy.CamelCase
        });

        var response = req.CreateResponse(HttpStatusCode.OK);
        response.Headers.Add("Content-Type", "application/json; charset=utf-8");
        await response.WriteStringAsync(json);
        return response;
    }
}

using Azure;
using Azure.Communication.Email;
using Azure.Identity;
using Microsoft.Extensions.Configuration;

namespace FilBackupStatusApi.Services;

/// <summary>
/// Sender mail via Azure Communication Services Email - ikke SMTP. To
/// autentificeringsmåder understøttes:
///
/// 1) AcsConnectionString sat -> bruges direkte (simplest til lokal test,
///    eller hvis jeres SWA-niveau ikke understøtter Managed Identity for
///    integrerede Functions).
/// 2) AcsEndpoint sat (uden connection string) -> DefaultAzureCredential
///    bruges i stedet, dvs. Managed Identity i Azure, eller jeres "az login"
///    når I kører lokalt. INGEN hemmelighed gemt noget sted i dette tilfælde.
/// </summary>
public class EmailSender
{
    private readonly IConfiguration _config;
    private readonly Lazy<EmailClient> _client;

    public EmailSender(IConfiguration config)
    {
        _config = config;

        // Bygges først ved første faktiske afsendelsesforsøg, ikke her i
        // konstruktøren - så mangler ACS-opsætningen endnu, fejler det først
        // inde i SendAsync, hvor ReportFunction allerede fanger fejlen og
        // lægger mailen i kø i stedet for at hele kaldet vælter.
        _client = new Lazy<EmailClient>(BuildClient);
    }

    private EmailClient BuildClient()
    {
        var connectionString = _config["AcsConnectionString"];
        var endpoint = _config["AcsEndpoint"];

        if (!string.IsNullOrWhiteSpace(connectionString))
        {
            return new EmailClient(connectionString);
        }

        if (!string.IsNullOrWhiteSpace(endpoint))
        {
            return new EmailClient(new Uri(endpoint), new DefaultAzureCredential());
        }

        throw new InvalidOperationException("Hverken AcsConnectionString eller AcsEndpoint er sat i konfigurationen.");
    }

    public async Task SendAsync(string subject, string body)
    {
        var from = _config["NotifyEmailFrom"] ?? throw new InvalidOperationException("NotifyEmailFrom mangler i konfigurationen.");
        var to = _config["NotifyEmailTo"] ?? throw new InvalidOperationException("NotifyEmailTo mangler i konfigurationen.");

        var message = new EmailMessage(
            senderAddress: from,
            content: new EmailContent(subject) { PlainText = body },
            recipients: new EmailRecipients(new[] { new EmailAddress(to) }));

        var operation = await _client.Value.SendAsync(WaitUntil.Completed, message);

        if (operation.Value.Status != EmailSendStatus.Succeeded)
        {
            throw new InvalidOperationException($"ACS Email-afsendelse fik status: {operation.Value.Status}");
        }
    }
}

using Azure.Data.Tables;
using FilBackupStatusApi.Models;
using Microsoft.Extensions.Configuration;

namespace FilBackupStatusApi.Services;

public class PendingEmailStore
{
    private readonly TableClient _table;

    public PendingEmailStore(IConfiguration config)
    {
        var connectionString = config["AzureWebJobsStorage"]
            ?? throw new InvalidOperationException("AzureWebJobsStorage mangler i konfigurationen.");

        var serviceClient = new TableServiceClient(connectionString);
        _table = serviceClient.GetTableClient("PendingEmails");
        _table.CreateIfNotExists();
    }

    public async Task EnqueueAsync(string subject, string body)
    {
        var entity = new PendingEmailEntity
        {
            Subject = subject,
            Body = body,
            QueuedUtc = DateTime.UtcNow
        };
        await _table.AddEntityAsync(entity);
    }

    public async Task<List<PendingEmailEntity>> GetAllAsync()
    {
        var results = new List<PendingEmailEntity>();
        await foreach (var entity in _table.QueryAsync<PendingEmailEntity>(e => e.PartitionKey == "pending"))
        {
            results.Add(entity);
        }
        return results;
    }

    public async Task DeleteAsync(PendingEmailEntity entity)
    {
        await _table.DeleteEntityAsync(entity.PartitionKey, entity.RowKey);
    }
}

using Azure.Data.Tables;
using FilBackupStatusApi.Models;
using Microsoft.Extensions.Configuration;

namespace FilBackupStatusApi.Services;

public class TableReportStore
{
    private readonly TableClient _reportsTable;
    private readonly TableClient _latestTable;

    public TableReportStore(IConfiguration config)
    {
        var connectionString = config["AzureWebJobsStorage"]
            ?? throw new InvalidOperationException("AzureWebJobsStorage mangler i konfigurationen.");

        var serviceClient = new TableServiceClient(connectionString);
        _reportsTable = serviceClient.GetTableClient("Reports");
        _latestTable = serviceClient.GetTableClient("LatestStatus");
        _reportsTable.CreateIfNotExists();
        _latestTable.CreateIfNotExists();
    }

    public async Task AppendAsync(ReportEntity report)
    {
        // Gem den fulde historik FØRST, uanset om mailen bagefter lykkes
        await _reportsTable.AddEntityAsync(report);

        var latest = new LatestStatusEntity
        {
            RowKey = report.PartitionKey, // kundenavn
            MovexNumber = report.MovexNumber,
            Subject = report.Subject,
            Body = report.Body,
            EventTimestampUtc = report.EventTimestampUtc,
            ReceivedUtc = report.ReceivedUtc
        };
        await _latestTable.UpsertEntityAsync(latest);
    }

    public async Task<List<LatestStatusEntity>> GetLatestAsync()
    {
        var results = new List<LatestStatusEntity>();
        await foreach (var entity in _latestTable.QueryAsync<LatestStatusEntity>(e => e.PartitionKey == "Status"))
        {
            results.Add(entity);
        }
        return results;
    }

  const STORAGE_KEY = "filbackup_api_key";
  const loginBox = document.getElementById("loginBox");

  const apiKeyInput = document.getElementById("apiKeyInput");
  const loginButton = document.getElementById("loginButton");

  const refreshButton = document.getElementById("refreshButton");

  const errorBox = document.getElementById("errorBox");

    // sessionStorage ryddes når fanen lukkes - nøglen gemmes IKKE permanent
    // på disken, og ligger aldrig i selve siden/koden.
    return sessionStorage.getItem(STORAGE_KEY);

  function showDashboard() {

    const key = apiKeyInput.value.trim();
    if (!key) return;

    apiKeyInput.value = "";
    showDashboard();
  });

  apiKeyInput.addEventListener("keydown", (e) => {
    if (e.key === "Enter") loginButton.click();
  });

  logoutButton.addEventListener("click", () => {

    showLogin();

  refreshButton.addEventListener("click", loadStatus);

  function classify(subject) {
    const s = (subject || "").toLowerCase();
    if (s.includes("fejl")) return { cls: "error", label: "Fejl" };
    if (s.includes("ingen ny backup") || s.includes("uændret")) return { cls: "warn", label: "Ingen ny backup" };
    return { cls: "ok", label: "OK" };
  }

  function formatDate(iso) {
    if (!iso) return "-";
    const d = new Date(iso);
    if (isNaN(d.getTime())) return iso;
    return d.toLocaleString("da-DK");
  }

  function escapeHtml(str) {
    const div = document.createElement("div");

    const key = getStoredKey();
    if (!key) { showLogin(); return; }

    errorBox.style.display = "none";
